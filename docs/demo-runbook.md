# WorkEcho demo recording guide

Use the worker and staff demo links in the README and fictional information. The three screenshots in the README are actual rendered app screens. A real-device voice recording has not been produced by the automated test run.

## A 90-second recording

1. **0–15 seconds — purpose:** explain that WorkEcho helps NGO teams preserve remembered stone-work histories for silicosis-related follow-up. Show the Healthcare track and source link in the README.
2. **15–35 seconds — actual Flow input:** focus the story field and use the installed Wispr Flow shortcut. Speak a fictional account in a language that works on this device. Keep the Flow interaction visible so viewers can distinguish dictation from pasted text.
3. **35–55 seconds — worker review:** choose saving and sharing options. If the app advertises Gemini availability, explain and choose the text-processing permission. Prepare the review and show the source excerpts beside the five fields. Read the details back to the worker.
4. **55–70 seconds — confirmation:** confirm the job and show that a return card exists. Keep the actual recovery code/QR out of any public recording, or invalidate the fictional code after filming.
5. **70-90 seconds - staff:** open the staff demo and find the **Demo interview** comparison containing the job just captured. Use a fictional story with a known demonstration peer so a relevant comparison exists. Show that the newly saved words reached staff, explain the shared clue and record a reasoned decision. Clearly distinguish any separate pre-seeded Worker A / Worker B example. Show approval controls for a simulated referral if time allows.

Record authenticated Notetaker import as a separate short clip after signing into the intended Wispr account. Import only a fictional interview, select the meeting and show the imported source. Redact unrelated meeting titles and account information. Link the published video in README only after checking its public playback and visibility.
